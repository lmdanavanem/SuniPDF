# Redaction

In 0.30.1, default hidden-data cleanup also removes XFA and replacement accessibility text
(`ActualText`/`Alt`) in retained page, form and pattern content/resources. The confirmation describes
this document-wide scope. Switching cleanup off shows a warning: sensitive duplicates may remain
outside the marked regions. Earlier files, backups and other copies need separate handling.

Draw or search for rectangles, then open Apply redactions. Choose the fill and optional intentional replacement text. Preview prepares and verifies **all** marked pages; the page selector shows the exact before/after candidate for one marked page. Apply commits those prepared bytes in one Undo step. Editing settings, changing documents, cancelling or closing invalidates the candidate. Cancellation is checked around rendering/cleanup and between pages, objects and painted rows; a single native rendering call must finish before cancellation takes effect. No source file is overwritten by preparation.

Uncomplicated visible, opaque Base14 Latin text is conservatively split into selectable glyphs at its original native positions. Only glyphs whose expanded bounds are completely outside every rectangle survive. Embedded fonts, shaping/spacing, clipping, semantic layers, OCR, images and nested objects use the established pixel-patch fallback. The preview reports both counts explicitly. The visible remainder survives; text within a fallback object's remainder may lose selection. Complex/unsafe cleanup graphs are refused atomically.

The default hidden-data cleanup removes metadata, structure text, attachments, scripts and outline/destination metadata using the shared verified sanitizer. Unused resources and previous revisions are pruned by a full rewrite. Turning cleanup off intentionally retains unrelated hidden data and is unsuitable when it might duplicate the redacted content. Intentional overlay text is inserted **after** residual-text verification. This release accepts up to 256 printable Latin characters, 4–200 pt; actual native font/glyph support and fit inside every rectangle are checked. There is no implicit font substitution or shaping.

**Keep unapplied PDF marks** stores standard `/Redact` annotations with their rectangles and fill. Content is still present and recoverable: saving marks is not applying redaction. Clear overlay text before persisting marks; persisted overlay/default-appearance fonts are explicitly unsupported. Marks are recovered when opening the PDF. Repeated persistence does not duplicate identical rectangles. Applying removes the overlapping marks. Removing a draft rectangle does not delete an already persisted annotation; use annotation deletion for that operation.

The document remains encrypted with its existing permissions. Prepared candidates also bind the original encryption dictionary/key identity. Preview and candidate limits are 128/160 MiB, at most 4,096 marks, 100,000 objects per page, 16,384 retained native glyphs and 40 million raster pixels per page. Undo deliberately retains the pre-redaction state in session memory; saved output and refreshed recovery files contain the cleaned state. Save a new copy and independently review it before distribution.

Regression coverage includes native selection, before/after identity, cancellation before commit, stale candidates, persistent marks, overlay refusal, OCR/image fallback, encrypted permission preservation and source-file integrity. Existing engine regressions cover nested forms, hidden resources and old revisions. Runtime results are reported by release CI; adding a test is not a passing result.
