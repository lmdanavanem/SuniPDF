| # | Date | Décision | Motif | Conséquences |
|---|---|---|---|---|
| D001 | kit initial | Workspace Rust, egui/eframe pour l'UI Windows | Rust natif, immédiat, DPI, AccessKit | Pas de WebView ni d'Electron |
| D002 | kit initial | Français par défaut, anglais disponible ; jamais de traduction du contenu PDF | Exigence produit | Catalogues JSON fr-FR / en-US |
| D003 | kit initial | Aucune copie de code PDFCraft sans audit de licence préalable | Obligations MIT/Apache + marques ArtCraft | `THIRD_PARTY_NOTICES.md` |
| D004 | kit initial | ~~Premier écran prototype sans rendu réel~~ | **Remplacée par D005** | — |
| D005 | 2026-10-13 | **Moteur PDF = PDFium** (build 7881, bblanchon/pdfium-binaries, sans V8/XFA) via `pdfium-render` 0.9.4, DLL chargée à l'exécution | Fidélité Chrome, ARM64 disponible, une API pour rendu/texte/formulaires/import de pages, pas de compilation C++ | DLL livrée à côté de l'exe ; un seul thread moteur ; chiffrement à l'écriture hors PDFium (P5) |
| D006 | 2026-10-13 | **Pas de fork de PDFCraft** ; reprise des principes (façade moteur, registre de commandes, sauvegarde atomique vérifiée, corpus) | Stack 0.7.x jeune, hayro vendored/patché, marque à retirer, surface énorme | Réévaluer une réutilisation ciblée de crates MIT/Apache (ex. `pdfcraft-crypt`) en P5 avec notices |
| D007 | 2026-10-13 | Repli pur Rust différé : `hayro` 0.8 + `lopdf` évalués en phase 6 seulement | Éviter deux moteurs avant qu'un seul soit solide | Pas de dépendance hayro aujourd'hui |
| D008 | 2026-10-13 | Cible de référence `x86_64-pc-windows-msvc` ; repli `stable-x86_64-pc-windows-gnu` + MinGW-w64 WinLibs (winget, utilisateur) tant que les Build Tools manquent | Seule voie sans droits administrateur | `scripts/dev-env.ps1` détecte MSVC ; Build Tools installés le soir même → override GNU retiré, MSVC actif |
| D009 | 2026-10-13 | La CLI parle anglais, sort du JSON et des codes d'erreur stables ; seule l'UI est bilingue | Outil d'automatisation, pas une interface utilisateur finale | `EngineError::code()` ; une option `--lang` pourra venir en P5 |
| D010 | 2026-10-13 | Backend graphique **glow (OpenGL)** pour eframe ; wgpu/DX12 désactivé | `wgpu-hal` 30.0.1 ne compile pas avec `gpu-allocator` 0.28 (crate `windows` incompatible) | Revoir en P6 (épingler gpu-allocator ou monter eframe) ; vérifier ARM64 |
| D011 | 2026-10-13 | Catalogues i18n embarqués par `include_str!` (pas de chargement de fichiers à l'exécution) | Un exécutable autonome, pas de fichier manquant possible | Changer une traduction = recompiler ; acceptable |
| D012 | 2026-10-13 | Préférences en JSON dans `%APPDATA%\SuniPDF`, écriture atomique ; SQLite seulement si des métadonnées volumineuses l'imposent | Zéro dépendance pour deux champs | `settings.rs::save_atomic` réutilisable |
| D014 | 2026-10-13 | Disposition inspirée de PDFCraft (onglets, barre de catégories, panneau d'outils, accueil à cartes, rail droit, palette Ctrl+K), sans copier ni code ni ressource | Demande explicite de l'utilisateur ; conventions de workbench PDF connues | `apps/sunipdf-desktop/src/shell.rs` ; aucune marque ni icône PDFCraft/Lucide |
| D015 | 2026-10-13 | Polices **système** Segoe UI / Segoe UI Semibold / Segoe Fluent Icons (ou MDL2) chargées depuis `C:\Windows\Fonts` à l'exécution ; repli polices egui + icônes texte | Look Fluent natif, zéro ressource embarquée, zéro question de licence | `icons.rs` ; l'app reste fonctionnelle sans ces polices (repli testé par construction) |
| D016 | 2026-10-14 | Chiffrement, déchiffrement et métadonnées via **lopdf** (MIT) sur les octets du document, résultat relu par PDFium ; AES-256 par défaut, AES-128 en option | PDFium ne chiffre pas à l'écriture ; lopdf implémente le gestionnaire de sécurité standard R2–R6 | `sunipdf-core::security` ; tests d'aller-retour obligatoires pour toute nouvelle transformation d'octets |
| D017 | 2026-10-14 | Icône originale dessinée par script (`scripts/make_icon.py`, Pillow) : page blanche à coin replié, « S » cyan, fond navy → bleu | Identité propre, reproductible, aucune ressource tierce ni licence à gérer | `assets/icon/` versionné ; régénérer avec le script en cas de changement |
| D018 | 2026-10-14 | Installateur **MSI WiX v3** (`packaging/wix`), construit en CI ; ZIP portable construit localement ; association `.pdf` limitée à « Ouvrir avec » | WiX 3 préinstallé sur les runners GitHub ; ne pas s'imposer comme lecteur par défaut | MSI jamais testé localement tant que WiX n'est pas installé en session admin |
| D013 | 2026-10-13 | Propriété des catalogues i18n : agent **ui-ux** ; les autres agents proposent leurs clés sous leur préfixe | Un seul responsable de la cohérence des textes | Voir `I18N.md` |
