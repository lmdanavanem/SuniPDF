# Tranche « review-fixes » : correctifs des revues adverses du 2026-10-14 (cœur, interaction, dialogues, E/S)

Quatre revues indépendantes (agent qa-performance, lecture seule, scénarios tracés dans le code et, pour le
moteur, rejoués par ctypes sur `pdfium.dll` 7881) ont produit les constats ci-dessous. Chaque constat donne le
fichier, le scénario, la vérification faite et le correctif suggéré. Ils complètent la première revue
(sécurité / CLI / onglets / packaging), déjà corrigée dans les commits `964d335` et `9593145`.

## Consignes pour l'implémenteur

1. **Vérifier d'abord l'état réel** : des tranches livrées depuis la revue (hub d'outils, édition avancée avec
   module de géométrie, vue continue) ont pu corriger certains points, notamment la géométrie des pages
   pivotées / rognées, l'opacité réinitialisée par `set_object_style`, `duplicate_object`, la sélection
   d'objet et les raccourcis. Pour chaque constat : rejouer le scénario sur HEAD ; s'il est déjà corrigé,
   ajouter seulement le test qui le prouve (s'il manque) et passer au suivant.
2. Corriger **à la racine** (fonction partagée plutôt que chaque appelant), chaque correctif couvert par un
   test (moteur : relecture du texte ou pixels rendus ; interface : test egui sans fenêtre quand c'est possible,
   sinon capture d'écran inspectée).
3. Ordre conseillé : constats `high` du moteur (`edit.rs`, `stamp.rs`, `security.rs`), puis `high` de
   l'interaction (Ctrl+Maj+S, sélection persistante), puis les `medium`, puis les `low`. Les constats déjà
   couverts par une tranche en cours sont listés dans `docs/NEXT_TASKS.md` s'ils restent ouverts.
4. Points demandant une décision (prendre le choix indiqué, le consigner dans `docs/DECISIONS.md`) :
   - Extraction / division d'un document protégé : le résultat n'est pas chiffré (PDFium copie des pages dans
     un document neuf). Choix : conserver ce comportement, l'annoncer (message d'état dans l'interface,
     champ `"encryption_removed": true` dans le JSON de la CLI) et le documenter dans le guide ; proposer la
     commande Protéger dans le message.
   - Mot de passe non Latin-1 avec AES-128 : refuser avec une erreur typée et un message (« AES-128 n'accepte
     que les caractères Latin-1 ; utilisez AES-256 »), jamais tronquer silencieusement.
   - `set_metadata` et XMP : régénérer un paquet XMP minimal (dc:title, dc:creator, dc:description,
     pdf:Keywords) cohérent avec /Info quand un flux XMP existe ; `strip_metadata` retire aussi les XMP de
     pages et d'images et `/PieceInfo`.
   - `add_text` : les sauts de ligne produisent plusieurs objets texte (interligne 1,2 × taille) ; un caractère
     hors WinAnsi est signalé (erreur typée `unsupported_characters` listant les caractères) plutôt que remplacé
     par « ÿ », sauf si une police système incorporée (tranche édition avancée) peut le rendre.
   - Permissions : la copie pour l'accessibilité (bit 10) reste toujours accordée.
   - Zoom clavier d'egui : désactiver `zoom_with_keyboard` dans les options du contexte.
5. Documentation : `CHANGELOG.md` (« Non publié », section « Corrigé »), `docs/KNOWN_ISSUES.md` (retirer ce qui
   est corrigé, ajouter les limites assumées), `docs/PROJECT_STATUS.md`, guides si un comportement visible
   change (extraction d'un document protégé, mots de passe AES-128).

### [high] Ctrl+Shift+S (Save As) saves over the original file when any text field has focus
- apps/sunipdf-desktop/src/app.rs:630
- Scénario : A user edits a document (dirty), types in the find bar (the find field keeps focus, and after Enter `focus_requested` gives it back), then presses Ctrl+Shift+S to save a copy. handle_input takes the 'a field has focus' branch (line 622). - Vérification : Traced handle_input from line 612: the first guard does not apply, and `ctx.memory(|m| m.focused().is_some())` is true, so the loop at about line 634 runs `consume_key(Modifiers::COMMAND, Key::S)`. The doc comment at line 717 says extra Shift and Alt are ignored and that Cmd-Shift-S must be checked before Cmd-S. modifiers.rs:211 matches_logically only rejects a missing shift, not an extra one. Counter-evidence: the main branch (line 742) does register COMMAND|SHIFT S before COMMAND S, but this early-return branch never reaches it. There is no test of keyboard routing, and nothing in KNOWN_ISSUES. The known 'Save As path reverting' item is a different bug.
- Correctif : In the focused-field branch, consume `Modifiers::COMMAND | Modifiers::SHIFT, Key::S` → Command::SaveAs before the COMMAND+S entry (turn the table into (Modifiers, Key, Command) triples, ordered most specific first).
